Sorting is to arange items in an expected order
Selection Short : For each pass, we swap the smallest item in the unsorted region with the first item in the region. N item -> n-1 pass
Takes n^2 time Complexity
Bubble sort : For each pass, travel from the beginning to the end of the unsorted region, we check for overlap pairs, and if there is an inversion then we swap
Takes n^2 time complexity
If there is no inversion in the pairs, the array is SORTED and we should STOP
We can improve Bubble Sort via adding a flag to assume the array is sorted, if the assumption is correct then we return flag. Otherwise, if the flag is wrong then we swap and assume the flag is correct once we move on
Insertion Sort : Start from index 1, pick a key and move back to the beginning of the array. If we catch a larger number, then shift it to the right and if we catch a smaller number then STOP and INSERT THE KEY there
Insertion Sort takes n^2 big O  
Comparison based Sorts : Directly compare A to B to determine their relative order 
Iterative Algorithm : Implemented using loop statements

Merge Sort is a part of divide-and-conquer sorting algorithms family
Includes the Divide step and Conquer step(uses the idea of recursions)
In the Divide step, we divide the array into 2 halves. 
For the recursion step, we keep dividing them by half until they are only 1 item left(base-step) and sort the two halves. 
Finally conquer, we recursively merge the 2 sorted sub-arrays to form a sorted array. The items are aranged in the merging progress
Time Complexity O: nlog(n)
Space Complexity O: n
For each n-steps in the recursive trees, there is n writing steps

Quick Sort is a part of divide-and-conquer sorting algorithms family
Uses the concept of pivot(trung vị)
Given an array, we pick the first item to be the pivot, then we parition the array into 2 parts so items >= pivot go right, <= pivot go left
Reuse the quick sort recursively to handle the two parts then we can get the sorted algorithms.
*Note that left.length()!=right.length()

* How to Hash
* How to *resolve collisions(when two keys share the same hash value)

*Criteria for a good hash functions :
1. O(1)
2. Scatter keys evenly throughout the hash table
3. Fewer collisions(even 1% is a lot)
4. Need fewer slots(less space)

Perfect Hash Function : No collisions(impossible)

Several Approaches making Hash Functions :
- Uniform Hash Functions : Good for distributing keys across the hash table
-- Formula : Let k =[0,X), hash(k) =[km/X]

- Divison method : 
-- Formula : hash(k) mod m


How to pick m : PRIME and CLOSE TO POWER OF 2
- Multiplication method 
-- Formula : [m(kA-[kA])]
--- A is a real number (0,1)
--- Let A be the golden ratio is a good choice

For String, we simply sum up the ASCII values of the characters

Collisions are very common, thus you must learn how to handle them :
- Separate Chaining
- Linear Probing
- Quadratic Probing
- Double Hashing

Alpha : Load Factor(n(numbers of keys in the hash map)/m(numbers of nodes in ll in hashmap))

Linear Probing : When collision, put the data and key in the next empty slot

Lazy Deletion : 
- Occupied 
- Occupied but mark as deleted
- Empty

With lazy deletion in Linear Probing, it can create many consecutive occupied slots and increasing the running time of find/insert/deletion
--> This is called Primary Clustering

The probe sequence of this linear probing is :
hash(key)
(hash(key)+1)%m 
(hash(key)+n)%m

To avoid primary clustering, we can
hash(key)
(hash(key)+1*d)%m
(hash(key)+2*d)%m
(hash(key)+3*d)%m
(hash(key)+m*d)%m
Let d be a co-prime to m 

Quadratic Probing is the same, except we replace 1,2,3 to k^2

Problem of Quadratic Probing:
Of two keys have the same initial position, their probe sequence are the same -> Secondary clustering(not as bad linear probing)
